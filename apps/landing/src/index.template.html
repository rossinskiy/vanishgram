What you get

The basics of a modern messenger, built around not trusting the server.

Anonymous accounts

Your account is 12 words generated on your device. Nothing to link to your phone or inbox. Lose the words and the account is gone: there is no reset by design.

Encrypted on your device

Chats use the Signal protocol from the official libsignal library, with post-quantum key agreement. Keys change with each message. The server stores only ciphertext until the other device confirms delivery, then deletes it.

Delete for everyone

Remove a message from both sides, including any copy still waiting on the server. Disappearing-message timers are agreed by both people in the chat.

Groups and channels

Group chats use MLS, the IETF standard for group encryption: keys change whenever someone joins or leaves, and a removed member reads nothing after that. Channels for broadcasting, public or private.

Voice calls

Calls are encrypted between the two devices. Both screens show a short code derived from the call keys: read it aloud to rule out a middleman.

Two-step verification

Add an authenticator app and a cloud password. The password is checked with OPAQUE, so the server never receives it or anything that can be tested offline.

Honest about what the server sees

Privacy claims are only worth something when they include the limits.

The server cannot see

  • Message text, files and call audio.
  • Your 12 words or your private keys.
  • Group names, descriptions and pinned messages.
  • Your phone number or email: it never has them.

The server can see

  • Who messages whom, when, and roughly how big the message is.
  • Your usernames, group member lists and device list.
  • Your IP address while connected.
  • Public channel posts, which are public by design.

Early software. The encryption follows established designs but has not been independently audited. Do not rely on it where your safety depends on it. Read the privacy policy.

Installing on iPhone without the App Store

The .ipa is not signed, because signing needs an Apple developer account. A free tool signs it with your own Apple ID and installs it. 1. Install Sideloadly or AltStore on your computer. 2. Connect the iPhone with a cable and drag the .ipa into the tool. 3. Enter your Apple ID when it asks (it is used only for signing on your computer). 4. On the iPhone open Settings, General, VPN and Device Management, and trust your Apple ID. With a free Apple ID the app stops opening after 7 days and has to be installed again; AltStore can renew it automatically while your computer is on. Your data stays on the phone when you reinstall over the old copy.

Questions

Why is there no web version?

A website can change its code every time you open it, and that code would hold your keys. The apps ship their interface inside the installer, so what runs on your computer is what you downloaded.

What if I lose my 12 words?

The account cannot be recovered. A reset path would also be a way in for anyone else, so there is none. Write the words down and keep them somewhere safe. If you are signed in on another device, that device keeps working.

Does it work on a phone?

Yes. There is an Android app (an APK you install from the file) and an iPhone build that you install yourself, see the download section. Both ship the interface inside the app and run the same encryption as the desktop app. On Android the app can notify you in the background; the notification only says that a message arrived and never shows its text. On iPhone, notifications only arrive while the app is open.

How is it paid for?

It is a free project. There is no advertising and no tracking, and nothing is sold.

Can I read the code?

Yes. The client, which does all the encryption, is open source: source code on GitHub (AGPL-3.0 for the app, GPL-3.0 for the shared parts). The installers on this page are built by GitHub Actions from that code. The server is not published, which is why the app is built so that the server never needs to be trusted with your content.

How do I report a security problem?

Follow the instructions in the security notes inside the repository: report privately and give steps to reproduce. Please do not run attacks against the live service.
